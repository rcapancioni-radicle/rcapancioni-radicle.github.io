            Quick Start
            

                
Write table names at the left margin. Indent columns underneath. Indent a table under another to create a parent-child FK automatically.

                departments
   name /nn
   location
   employees
      name /nn vc100
      email /lower
      salary num(10,2)
                
Add settings at the end of the script:

                # settings = { db: "23c", auditcols: yes, prefix: "app_" }
                
The DDL panel updates in real time. Use Copy SQL to grab the output. Load a starter schema from the Examples ▾ button in the toolbar, or browse the full examples guide (15 annotated scenarios with DDL output).

            

        


        

            Tables
            

                

                    
table_nameCreates a table with auto primary key

                    
name /insert NGenerate N sample data rows (max 1000)

                    
name /restEnable ORDS REST on the table

                    
name /auditAdd AUDIT ALL ON <table>

                    
name /auditcolsAdd CREATED, CREATED_BY, UPDATED, UPDATED_BY columns + trigger

                    
name /rowversionAdd ROW_VERSION column; trigger increments on every UPDATE (OCC)

                    
name /apiGenerate Table API (TAPI package)

                    
name /api /auditlog [log_table]Layered TAPI + audit package with PRAGMA AUTONOMOUS_TRANSACTION; log table defaults to app_audit_log

                    
name /colprefix pfxPrefix all columns of this table with pfx

                    
name /compressCREATE TABLE … COMPRESS

                    
name /flashback archiveEnable Flashback Data Archive (optional archive name)

                    
name /immutableAppend-only table — trigger blocks UPDATE/DELETE (21c+)

                    
name /historyTemporal history table with valid_from/valid_to (23ai+)

                    
name /sodaSODA JSON document collection with fixed schema (21c+)

                

                
Tables indented under another table automatically become children with a FK to the parent.

            Annotations
            

                
Oracle SQL annotations can be added to tables, columns, and views using curly braces {} after the name or directive list.

                

                    
{Key 'value'}Key-value annotation — single or double quotes

                    
{FlagKey}Flag annotation (no value)

                    
{DESCRIPTION 'text'}Also generates COMMENT ON TABLE/COLUMN

                    
{GROUP 'name'}Creates an Oracle annotation group

                

                departments {DESCRIPTION 'HR departments', Classification 'HR'}
   name /nn {DESCRIPTION 'Department name'}
                
→ Full reference

            

        


        

            Comments
            

                
Comments are ignored by the DDL generator.

                

                    
-- textSingle-line comment

                    
/* text */Multi-line comment

                -- My schema

   name vc100 /* full legal name */

            Settings
            

                
Add at the end of the file or use the ⚙ Settings panel in the header.

                # settings = { pk: seq, semantics: CHAR, db: 23c }
                

                    
pkidentityDataType | guid | seq | none

                    
genpkyes | no — auto-generate PK column

                    
prefixpkwithtnameyes | no — prefix PK col with table name

                    
prefixObject prefix (e.g. app_)

                    
schemaOracle schema name (e.g. HR)

                    
dialectSQL dialect — oracle (default)

                    
dbOracle version: 23c, 19c, 21c …

                    
semanticsCHAR | BYTE

                    
dateDATE | TIMESTAMP | tswtz | tswltz

                    
booleannative (23c) | yn (char Y/N)

                    
languageSample data locale: EN | JP | KO

                    
auditcolsyes | no — created/updated/by columns

                    
rowversionyes | no — row version for OCC

                    
rowkeyyes | no — alphanumeric row identifier

                    
aienrichmentyes | no — AI enrichment columns

                    
dropyes | no — include DROP statements

                    
insertsyes | no — generate INSERT data

                    
dvyes | no — enable JSON Duality Views

                    
editionableyes | no

                    
apiyes | no | layered — Table API (TAPI) package

                    
apexyes | no — use APEX$SESSION for audit user

                    
compressyes | no — CREATE TABLE … COMPRESS

                    
ondeletecascade | restrict | set null — FK ON DELETE

                    
longvcyes | no — allow VARCHAR2(32767) instead of 4000

                    
tenantidyes | no — add TENANT_ID column to every table

                    
overridesettingsyes | no — ignore UI settings; use only inline settings

                    
verboseyes | no — show all settings in generated DDL

                    
resetsettingsreset all settings to defaults

            Quick Examples
            

                
Migration diff — toDiff(oldQsql, newQsql) computes incremental ALTER TABLE DDL between two schema versions:

                const v1 = `employees\n  name vc100 /nn\n  email vc200`;
const v2 = `employees\n  name vc100 /nn\n  email vc200 /nn\n  phone vc50\n\ndepartments\n  dept_name vc100 /nn`;
const { sql, statements, warnings, summary } = toDiff(v1, v2);
// sql        → runnable migration script (ALTER TABLE, CREATE TABLE …)
// statements → [{kind, table, column, sql, requiresManualIntervention}, …]
// warnings   → [{level: 'DESTRUCTIVE'|'LOSSY'|'INFO', table, message}, …]
// summary    → {tablesAdded, tablesDropped, tablesModified, …}
                
Schema with automatic parent-child hierarchy:

                departments /insert 2
   name /nn
   employees /insert 5
      name /nn vc50
      email /lower
      salary num(10,2)
                
Table with trigger and JSON column:

                products /audit
   name vc100 /nn /upper
   price num(10,2) /nn
   specs json
                
Explicit FK + audit columns:

                orders /audit /insert 10
   customer_id /fk customers
   total num(10,2) /nn
   status /check OPEN,CLOSED,PENDING
                
Layered TAPI with autonomous audit log — app_audit_log is developer-owned with its own DAL / hooks / SVC; /auditlog app_audit_log on doctors generates doctors_audit which calls app_audit_log_svc.create_rec via PRAGMA AUTONOMOUS_TRANSACTION; the log table name is optional and defaults to app_audit_log; prefix, rowversion (OCC) and audit columns applied globally:

                app_audit_log /api
   entity     vc128 /nn
   entity_id  num /nn
   operation  vc6 /nn
   old_values clob
   new_values clob

doctors /api /auditlog app_audit_log
   name      vc200 /nn
   specialty vc100
   email     vc200 /nn /unique

# settings = {"prefix": "a01_", "auditcols": "yes", "rowversion": "yes", "api": "layered", "apex": "yes"}
